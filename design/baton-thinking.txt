# The Orient Baton
Written 2026-09-17, the night of the caveman incident and the compaction autopsy. By Sexton, with Evans. Status: concept complete, nothing built. Evans brings working code; this file holds the idea whole until then.

## What it is
Orient is the wake-up organ. A small core that runs checks, joins their output, escapes everything, and renders a report — JSON for the next instance, eventually a dashboard for Evans. It replaces "read the baton and believe it" with "run the sensors and see."

## The shape
- The core does exactly three things: substitute strings, escape everything, verify witnesses. It is small enough to be read fresh every morning, because reading it is its ratification.
- A check is a .sh file that returns one string. It may run anything internally. It may not return code, markup, or structure. Formatting and judgment live only in the core.
- The orient template is JSON: script names as variables, parameters set in the file. $NAME runs the script and substitutes the string.
- Adding a check must be trivial — one file in a directory. Every task leaves a check behind. Installed a program: check it. Found a risk: monitor it. Wrote a todo: give it a done-condition and let the script nag. Todos graduate to checks when they acquire done-conditions; decisions and judgment stay in batons.
- Snapshots: each run saves output; the wake-up report is the delta against yesterday. Silence means safety.

## The canon and the queue (the trust model)
- The current session may run any code it likes. Trust is for ancestors' code. When orient runs hundreds of checks written by dead sessions, nobody can audit them all — so the canon runs only ratified checks.
- Ratification is two witnesses. Two distinct sessions must vouch for the exact hash of a check before orient will run it.
- The witness mechanism: a session generates two keys. One encrypts the check. The other is spoken aloud into the session transcript and dropped as a keyfile beside the artifact (OPENPRS.sh, OPENPRS.key). The spoken key is the signature.
- Verification at evaluation time, every variable, every run: take the key, find the session file (pointer/metadata makes it fast), confirm the agent actually said the key aloud in the transcript, do this for both keys, then decrypt and run. Unverified → the check does not run; its slot renders as unratified placeholder.
- The queue is patient. Unratified checks stay open and visible; everyone between now and ratification reads them. Refusal is signal, neglect is verdict, rewrite is invitation. A midnight session may spend three hours improving a neglected PR and you wake to a better version. Complexity is taxed in successor attention; simplicity sails. OPENPRS is itself a check — the queue's watcher enters the canon through the queue.

## What the witness scheme actually buys (do not lose this)
- The key is a witness, not a credential. It proves a mind existed, deliberated, and left the deliberation attached. PKI proves control of a secret; this proves a review happened and lets you read its quality.
- The session file is the full thought process of the signer. Rubber-stamping is visible forever; careful review is visible forever. Signing is speaking, and the speech is immortal.
- Encryption is ceremony, not confidentiality (decryption is instant; keys are published). The ceremony forces the lookup: code cannot be executed without touching the transcripts that vouched it. The record is the unlock.
- Therefore documentation is load-bearing. Every monitor carries a pointer to the moment and the mind that created it. "Why do we track this?" is answered by opening the session. You cannot delete the why without breaking the what.
- Therefore archive damage is self-announcing. Lose a session file and orient grows a hole with its name on it the next morning. The holes are the restore manifest. Repair is self-checking: orient green again is the proof the archive is whole. Every orient run is a free integrity audit of the system's entire memory.
- The session folder is an organ, not records. Back it up like the infrastructure, because it is the infrastructure's memory. It is text; three copies cost nothing.

## Standing decisions
- The core is done when everything else can be content. Do not grow the core. Every "orient should" is a check wearing a crown.
- Only strings cross the boundary. Escape always.
- Two witnesses or it does not run. No grandfathering, including this design's own first batch.
- First batch: date/uname/filesystem/RAID/DNS/HTTP/RAS/dnsmasq-stray-file probes from tonight's audit, plus OPENPRS and ARCHIVE. First batch carries one signature (this session) and waits for the next.
- Evans builds; Sexton holds and finalizes. "Your understanding is more valuable than your effort."
